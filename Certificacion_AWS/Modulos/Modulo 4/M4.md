### Expansión global con la infraestructura de AWS
#### Cómo elegir una región o un conjunto de regiones
Si tuviérmos que ampliar nuestra cafetería abriendo nuevas ubicaciones, habría varias cosas a tener en cuenta, como la demanda de la clientela y el coste del desarrollo. De misma manera hay que tener encuanta con varios factores a la hora de seleccionar una región o conjunto de regiones para tus recursos reales

#### Ubicaciones periféricas de AWS
Al igual que nuestra franquicia de café podría expandirsecon versiones más pequeñas de la tienda como carritos de café moviles, AWS cuenta con instalaciones de menor tamaño denominadas ubicaciones periféricas. Estas, almacenan en caché elementos como imágenes, videos y otros recursos para que los usuarios puedan acceder l contenido que necesitan con una latencia más baja.
(Las ubicaciones periféricas sirve para acercar el contenido al usuario, por ejemplo, puedes tener una imagen en un S3 que este en ohio, pero un cliente quiere acceder desde madrid. Esto sería muy lento. Sin embargo, CloudFront copia esas imágenes a una ubicación periférica, en Madrid y de esta manera el usuario accederá a esta imagen con menor latencia)

#### Infraestructura como código y CloudFormation

AWS cuenta con servicios como CloudFormation, que puedes utilizar para automatizar el despliegue de los recursos en la nube. Estos son sercicios que utilizan la infraestructura cómo código o  IaC, lo que ayuda a lograr una configuración coherente y fiable cada vez que la empresa se expande
(CloudFormation es una herramienta que interpreta el código para construir una infraestructura de forma automática)

### Selección de las regiones de AWS
- Cómo elegir una región
#### Consideraciones clave a la hora de elegir regiones

1. Conformidad: 
Las diferentes ubicaciones geográficas tienen distintos requisitos normativos y leyes de protección de datoss que las organizaciones deben cumplir. Por ejemplo, el Reglamento General de Protección de Datos (RGPD), esta diseñado para proteger datos personales y la privacidad de las personas dentro de la UE(Union Europea). La conformidad con el RGPD incluye obtener el consentimiento adecuado para la recopilación de datos y proporcionar mecanismos para el acceso y la eliminación de los datos.

2. Proximidad: 
Debes tener en cuenta cómo lograr una latencia baja para tus usuarios. Las regiones más cercanas a tu base de usuarios minimiza el viaje de datos, lo que reduce la latencia y mejora la capacidad de respuesta de las aplicaciones. 

3. Disponibilidad de características:
También hay que considerar qué características y servicios específicos están disponibles en cada región. AWS amplía las características y servicios conctantemente en varias ubicaciones, pero no todas las regiones contienen taodas las ofertas de AWS. Por ejemplo, en una tienda de EEUU venden diferentes productos y uno de ellos es una pistola porque sus leyes lo permite y solo lo distribuyen en su país.
Por este motivo las regiones especiales como (GovCloud) están pensadas solo para clientes con requisitos de seguridad muy altos

4. Precios:
Algunas regiones tienen costes operativos más bajos que otras. Tales costes operativos pueden afectar a los gastos generales de alojamiento de aplicaciones y servicios. Las leyes y normativas fiscales también pueden influir en el coste. Las leyes de soberanía de los datos de ciertas regiones pueden requerir que los datos se almacenen de forma local, lo que afecta tanto a la conformidad como al coste.
